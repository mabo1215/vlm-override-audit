# vlm-override-audit

Code and per-expression records for

> Bo Ma, Wei Qi Yan and Jinsong Wu. *When May a Re-ranker Override a
> Vision-Language Model? A Harm Audit for Visual Grounding.* Submitted to
> *Applied Sciences* (MDPI), 2026.

The paper audits how often a re-ranker that overrides a vision-language
model (VLM) breaks a box that was already correct.  A switching threshold is
chosen on one image set, frozen, and tested once on new images with an exact
(Clopper--Pearson) upper bound on harm among switches.  This repository holds
everything needed to recompute every count, bound, table and diagnosis
figure of the paper on a CPU, and the code that generated the second system
(System B).

## Contents

| Path | What it is |
| --- | --- |
| `experiments/cs2_audit/` | The audit, the diagnostics, the trained verifier V1, System B's generation and label-join code, and the scripts that write every table and figure. |
| `experiments/cs2_audit/configs/` | `audit_records.json` (which record file and frozen threshold each analysis uses), `system_b_protocol_v1.json` (System B's protocol file, final version), `authoritative_counts.json`. |
| `experiments/cs2_audit/results/` | The audited records (one expression per image) and every computed result the tables read. |
| `data/system_a/` | System A's expression-level records and candidate sets (below). |
| `data/system_b/` | System B's generation records for G1 (the COCO records), G2 (the verifier's training pool) and G3 (RefCLEF). |
| `data/coco/` | COCO licence ids of the RefCOCO+ confirmation images (used to choose Figure 1). |
| `docs/` | System A's settings, System B's protocol file with its version history, and the provenance timeline. |
| `paper/figs/` | The tables and figures of the submitted paper, as generated by the commands below. |

Not included: images, ground-truth boxes, referring-expression text and
model weights.  They are available from their providers: COCO
(<https://cocodataset.org>), RefCOCO, RefCOCO+ and RefCOCOg (Yu et al.,
2016; Mao et al., 2016), RefCLEF/ReferItGame (Kazemzadeh et al., 2014) on
SAIAPR TC-12 photographs, and the models on Hugging Face at the revisions in
the protocol file.  System A's generation pipeline is not part of this
release; its settings are listed in `docs/system_a_settings.md`, and its
outputs are released as candidate sets.

## Setup

Python 3.12 and the CPU packages in `requirements.txt`:

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
python -m unittest discover -s experiments -t . -p "test_*.py"
```

The tests include `test_release_records.py`, which checks that the
legacy source-row reduction of the released expression-level records
reproduces every registered audit record (review item J9) and that the
released candidate IoUs reproduce System A's and System B's audited
records; `test_record_rules.py` checks the record consistency rules (J7).
The frozen verifier `v1.pkl` was saved with scikit-learn 1.8.0; load it with
that version.

## Reproducing the paper

Run from the repository root.  Each command overwrites the result it
produces; `git status` afterwards shows no change.

| Paper output | Command |
| --- | --- |
| Tables 3 and 4 (images per set; shared images) | `python -m experiments.cs2_audit.data_tables` (prints both) |
| Controlled study, risk--coverage, power (inputs of Tables 7, 9, 10, A5 and Figures 4--5) | `python -m experiments.cs2_audit.diagnose_failure` (about 3 minutes) |
| Continuous IoU (input of Table A4) | `python -m experiments.cs2_audit.audit_revision_cpu` |
| Listwise score (input of Table A3) | `python -m experiments.cs2_audit.listwise_check --release-records data/system_a --output experiments/cs2_audit/results/listwise_check_20261016.json` |
| Counts and bounds of both systems (inputs of Tables 5, 6, 8, 11, A2) | `python -m experiments.cs2_audit.paper_numbers` |
| System B diagnostics (inputs of Table 12, A8 and Figure 6) | `python -m experiments.cs2_audit.system_b_diagnostics` |
| V1 diagnostics, LTT comparison, V1 on System A (inputs of Table 13 and Figure 5b) | `python -m experiments.cs2_audit.system_b_analysis --protocol experiments/cs2_audit/configs/system_b_protocol_v1.json --arm G1 --joined experiments/cs2_audit/results/system_b_20261016/joined --system-a-predictions experiments/cs2_audit/results/system_b_20261016/v1/v1_predictions_system_a.csv --output experiments/cs2_audit/results/system_b_20261016/g1_secondary_analysis.json` and the same with `--arm G3` (without `--system-a-predictions`) and `--output .../g3_secondary_analysis.json` |
| Figures 4, 5 and 6; Tables 7, 9 and A5 | `python -m experiments.cs2_audit.make_diagnosis_figures` |
| Tables 5, 6, 8, 10--14 and A1--A4, A7, A8 | `python -m experiments.cs2_audit.write_paper_tables` |
| Figure 1 | see below |

Tables 1 and 2 describe the two systems (`docs/system_a_settings.md` and the
protocol file); Table A6 (the OWLv2 generator) and Table A9 (the default-box
coordinate check, from `results/default_frame_check_20261016/`) are written in
the paper text.

### Figure 1

The examples are chosen without looking at outcomes: within each category
(help, harm, no switch) of System A's RefCOCO+ confirmation set, images are
ordered by SHA-256 of a fixed seed, the category and the image id, and the
first image is shown whose COCO licence is 4, 7 or 8 and whose Flickr page
still credits the creator under CC BY.  The Flickr checks are recorded in
`results/qualitative_flickr_checks_20261018.json`.

```bash
python -m experiments.cs2_audit.qualitative_figure select \
  --licenses data/coco/refcocoplus_confirmation_licenses.csv \
  --release-records data/system_a \
  --flickr-checks experiments/cs2_audit/results/qualitative_flickr_checks_20261018.json \
  --output selection.json          # same images, boxes and IoUs as the committed selection
python -m experiments.cs2_audit.qualitative_figure render \
  --selection experiments/cs2_audit/results/qualitative_selection_20261018.json \
  --image-root <COCO train2014 folder> --output paper/figs/fig1_examples.pdf
```

Rendering needs the three COCO images and uses the expression text and
ground-truth boxes stored in the committed selection file.  Photographs:
"De gulden middenweg" by Emanuello Brigant, "cut" by Linda Hartley and
"Colchester Zoo - Zebras" by Paul Williams, all CC BY 2.0, via COCO.

## Data

### System A (`data/system_a/`)

System A is the Qwen2.5-VL-7B-Instruct re-ranker of the paper's original
study (settings in `docs/system_a_settings.md`).

`<benchmark>_expressions.csv.gz`, one row per scored expression (4,700, 4,699
and 4,698 rows for RefCOCO+, RefCOCOg and RefCOCO), in generation order:

| Column | Meaning |
| --- | --- |
| `split` | `train`, `select`, `certify` or `confirm` |
| `image_id` | COCO image id |
| `expression_id` | RefCOCO-family reference id |
| `score` | switch score $s$ (nats); 0 when no candidate beats the default by $10^{-6}$ |
| `baseline_iou` | IoU of the default box with the ground truth |
| `challenger_iou` | IoU of the alternative box (equals `baseline_iou` without a switch) |

The audited records are these rows reduced to one expression per image with
`python -m experiments.cs2_audit.reduce_manifest --rule legacy-source-row
--seed <seed>` (seeds 20270822, 20270823 and 20270824).

`<benchmark>_candidates.jsonl.gz`, one object per expression: `coco_image_id`,
`ref_id`, `set`, `file_name`, `candidate_boxes` (normalized
$[x_1,y_1,x_2,y_2]$), `candidate_sources` (`restricted` is the VLM's default,
`detector_expr` a GroundingDINO proposal), `candidate_pairwise_scores`
($\theta$), `candidate_listwise_posteriors`, `candidate_ious`,
`default_index`, `alternative_index` and `switch_score`.

### System B (`data/system_b/`)

System B is InternVL3-8B, specified in
`configs/system_b_protocol_v1.json` before any of its labels was read (see
`docs/system_b.md`).  Each record of
`g1_records.jsonl.gz` (the 13,302 COCO records of System A, all four sets),
`g2_records.jsonl.gz` (12,483 expressions on 4,000 further COCO training
images, used only to train V1) and `g3_records.jsonl.gz` (9,999 RefCLEF test
images) holds the generation output without text: `record_key`
(`<benchmark>:<reference id>`), `split`, `image_id`, `candidates` (box and
source), `default_index`, the pairwise preferences `theta` and switch
`chosen_index` and `switch_score`, the listwise `phi`,
`listwise_chosen_index` and `listwise_switch_score`, the sampled and
detector boxes, cost fields, and `candidate_ious` added afterwards.  The
assembled audit manifests, V1 and its predictions, and the label-join log are
in `results/system_b_20261016/`.
